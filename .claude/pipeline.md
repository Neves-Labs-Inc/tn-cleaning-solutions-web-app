# Pipeline notes

## Commands
- Unit tests: `npm test` (node --test over tests/**/*.test.ts). PDF tests must stay on `node --test`: `tsx` can't load `@react-pdf/hyphenate`.
- Typecheck: `npx tsc --noEmit`. Lint: `npm run lint`.
- DB tests (pgTAP): `supabase start` then `supabase test db` (tests in `supabase/tests/database/`). Needs Docker running.
- DB types: `supabase gen types typescript --local > src/types/database.ts`; check with `npm run db:check-types`.

## Gotchas
- Parallel worktrees each get their own local Supabase: `supabase/config.toml` has `project_id = "web-app-wtNN"` and ports shifted to 55xxx (wt-01) / 56xxx (wt-02); the file is marked `--skip-worktree` so the change never lands. Don't commit or revert it. Run `supabase stop` (in your own worktree only) when done.
- Worktree `node_modules` is a symlink to the main tree: don't delete it. Turbopack rejects it, so run `next dev --webpack -p <unique port>` with `BETTER_AUTH_URL=http://localhost:<port>`.
- `.env.local` has `NEXT_PUBLIC_SUPABASE_ANON_KEY` but the code reads `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`; set it in the environment for dev runs (the local Supabase anon key from `supabase status`).
- Only stop processes you started (by PID). Never `pkill -f next` or stop another worktree's Supabase.
- `src/types/database.ts` is regenerated by several tickets; on merge, regenerate rather than hand-merge.
- No Playwright in the repo; `playwright-core` with the cached browser in `~/Library/Caches/ms-playwright` works from a scratchpad install.
- Another project's Supabase (`supabase_db_drizzle-baseline`) held port 55322; Franklin had it stopped on 2026-11-23. If `supabase start` fails on a port, check `docker ps` for a stray project before anything else.
- `supabase gen types` rewrites the whole hand-maintained `src/types/database.ts`; coders hand-edit column lines instead and rely on `npm run db:check-types`.
- `psql` to a worktree's host port can hang; use `docker exec supabase_db_<project_id> psql -U postgres`. There's no `timeout` binary on this Mac.
- A fresh worktree Supabase has no users: run `npm run seed:admin` with `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:<api port>` and `SUPABASE_SECRET_KEY` from `supabase status`, then insert fixtures by SQL with admin JWT claims.
- `supabase test db` on a DB a design reviewer seeded can fail on leftover rows; run `supabase db reset` first.
- The shared Playwright MCP browser keeps cookies per host, so dev servers on different localhost ports share logins; design reviewers should use playwright-core with a fresh context (cached chromium_headless_shell-1248 via executablePath).
- The main tree local DB may hold reviewer-made fixtures (e.g. a restrictive RLS policy on jobs to fake Unpriced). Run `supabase db reset` before relying on it. Seed admins with a throwaway address like admin@example.test.
